# Модуль 7. Отладка рантайма и жизненный цикл сессии

Помимо прямого чтения файлов базы и перехвата токена, в приложении есть еще три критических технических фактора.

## 1. Встроенный отладочный порт Chromium (CDP)

Разработчики кассы оставили включенной поддержку стандартных флагов командной строки Chromium. 

Если запустить исполняемый файл кассы с дополнительным ключом:
`"Касса МойСклад.exe" --remote-debugging-port=9222`

Приложение открывает локальный сетевой порт 9222 и поднимает CDP (Chrome DevTools Protocol - встроенный в браузер отладочный интерфейс для разработчиков).

### Как это выглядит на практике
Достаточно открыть на этом же компьютере обычный браузер по адресу:
`http://localhost:9222`

В окне браузера открывается стандартная панель разработчика (DevTools). В ней доступна вкладка Network (Сеть), где отображаются все исходящие запросы кассы, куки, сессионные токены и ответы сервера МоегоСклада в реальном времени. Для этого не требуется модифицировать бинарный файл или устанавливать драйверы перехвата.

## 2. Имитация проверок безопасности (envCheckWorker.js)

В составе дистрибутива кассы работает отдельный служебный фоновый процесс `envCheckWorker.js`. Он скачивает файл конфигурации с адреса:
`https://featureflag-electron-app.moysklad.ru/electron-app/envcheck-service-config.json`

### Анализ декомпилированного кода процесса
При исследовании функций этого воркера выяснилось, что он проверяет:
- Наличие служб фискализатора (ЕСМ, АТОЛ, Штрих-М).
- Наличие файлов библиотек драйверов принтеров (`fptr10.dll`, `DrvFR.dll`).
- Настройки страны и операционной системы.

В коде полностью отсутствуют базовые проверки безопасности:
- Нет проверки на подключение отладчика (Anti-Debugging).
- Нет проверки на запуск в виртуальной машине (Anti-VM).
- Нет проверки контрольной суммы или цифровой подписи файлов самого приложения (Integrity Check).
- Нет контроля подмены библиотек в памяти процесса.

## 3. Склейка авторизационной куки без подписи

В декомпилированном скрипте `web-retail-opt.js` обнаружен механизм формирования сессионной куки кассы:

```javascript
// Значение куки собирается простой текстовой конкатенацией (склеиванием строк):
un().cookie = "Lognex-Pos-Auth=" + d.ho + ":" + d.EL;
// d.ho - это логин сотрудника (uid)
// d.EL - это 40-значный токен кассы (authToken)
```

В структуре этой куки:
- Отсутствует HMAC (хэш-код проверки подлинности сообщения с использованием секретного ключа сервера).
- Отсутствует цифровая подпись даты и времени создания.
- Отсутствует привязка к аппаратному отпечатку компьютера (Hardware Fingerprint).
Это простая текстовая связка логина и токена, разделенная двоеточием.

## 4. Что сжигает сессионный токен кассы

Токен кассы обладает длительным сроком службы, но мгновенно теряет силу при определенных действиях:

### Токен НЕ сгорает:
- При обычном закрытии окна кассы на крестик.
- При перезагрузке компьютера или отключении питания.
- При смене сетевого IP-адреса компьютера (например, переключение с проводного интернета на мобильную точку доступа).
- При отправке фоновых запросов чтения с других компьютеров.

### Токен СГОРАЕТ на сервере:
1. **Явный логаут:** Кассир нажал кнопку "Выход" в меню приложения кассы. Сервер инвалидирует (аннулирует) сессионный токен в базе данных.
2. **Смена пароля учетной записи:** Если администратор в веб-интерфейсе меняет пароль кассира, МойСклад принудительно сбрасывает все активные токены этого сотрудника.
3. **Отвязка кассы:** Администратор в веб-панели магазина нажал кнопку "Сменить токен" или "Отвязать кассу" в свойствах точки продаж.
