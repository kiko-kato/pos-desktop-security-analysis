# Модуль 2. Утечка сессионных токенов на диске

Когда сотрудник входит в кассу, сервер выдает ему Bearer-токен (цифровой сессионный пропуск из 40 символов, который программа показывает серверу при каждом действии вместо повторного ввода логина и пароля).

## Как устроена правильная защита в Windows (DPAPI)

В браузере Google Chrome пароли и сессионные куки шифруются системным механизмом DPAPI (Data Protection API - встроенный криптографический сейф Windows). 

DPAPI использует мастер-ключ конкретного пользователя Windows. Если злоумышленник просто скопирует файл кук на флешку и откроет на другом компьютере, он увидит зашифрованный шум, потому что вне этой учетной записи ключ расшифровки не работает.

## Как разработчики обошли собственную защиту

Создатели кассы не стали использовать защищенный механизм кук для основного ключа авторизации. Вместо этого они записали токен в LocalStorage (встроенный в браузер блокнот для хранения настроек сайтов).

В операционной системе этот блокнот сохраняется на диске в формате LevelDB (простая дисковая база ключ-значение от Google) по пути:
`%APPDATA%\moysklad-kassa\Local Storage\leveldb\`

В этих файлах сессионный токен лежит в формате Plaintext (абсолютно открытый текст без какого-либо шифрования).

## Построчный разбор дампа файла LevelDB

Ниже приведен реальный фрагмент дампа байтов из файла `017431.ldb`, извлеченного из папки кассы без прав администратора:

```text
OFFSET 216:
... \x01:mode\x01$\xcd\x05CL\x01LIST         // Служебные заголовки формата базы LevelDB
\x0a\x11)authToken                              // Имя сохраненного параметра: токен авторизации кассы
\x01W\x0b\x01\xb5\xd8\x00\x01              // Служебные байты длины строки
008911e9...[хвост]                                // Сам 40-значный секретный ключ кассы в открытом виде
\x0a\x0f\x00crashed\x00\xb8                   // Служебный флаг проверки падения программы
tokenHostname                                     // Имя параметра: адрес сервера авторизации
online.moysklad.ru                                // Сам адрес сервера в открытом виде
currentUser                                       // Имя параметра: логин текущего сотрудника
cashier1@example.com                              // Логин кассира в открытом виде
retailStoreId                                     // Имя параметра: номер магазина в системе
83063f7d-c5d5-11f0-0a80-175b000399dd             // Уникальный идентификатор торговой точки
```

## Главная опасность

1. **Нулевой барьер доступа:** Чтобы прочитать этот файл, не нужны права администратора. Не требуется подтверждение UAC (всплывающее системное окно с вопросом "Разрешить этой программе внести изменения?").
2. **Фоновое копирование:** Любой фоновый скрипт или программа, запущенная под пользователем кассы, забирает ключ за доли секунды.
3. **Обход двухфакторной аутентификации:** Токен - это результат уже пройденной проверки. Сервер не требует подтверждения по СМС или почте при отправке запроса с готовым токеном.

## Жизненный цикл токена (когда он сгорает)

Токен не является вечным, но обладает высокой живучестью:

- **Токен живет и работает:** При закрытии приложения кассы, при перезагрузке компьютера, при обрывах связи и в течение недель непрерывной работы кассира.
- **Токен сгорает на сервере:**
  1. Если кассир нажал явную кнопку "Выход" (Logout) в меню кассы.
  2. Если администратор в веб-панели сменил пароль этой учетной записи (после смены пароля сервер сбрасывает все активные кассовые сессии).
  3. Если в настройках точки продаж нажали кнопку "Отвязать кассу" или "Сменить токен доступа".
