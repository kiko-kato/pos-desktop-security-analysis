# Модуль 2. Утечка сессионных токенов на диске

Когда кассир или администратор заходит в кассу, сервер выдает Bearer-токен (цифровой сессионный пропуск из 40 шестнадцатеричных символов, который касса показывает серверу при каждом запросе вместо логина и пароля).

## Как браузеры должны хранить секреты

В браузере Google Chrome авторизационные Cookies (сессионные куки) в Windows шифруются механизмом DPAPI (Data Protection API - системный встроенный сейф Windows, который шифрует файл на диске мастер-ключом пользователя системы). Без вызова системной функции расшифровать их на другой машине нельзя.

## Как это сделано в МоемСкладе

Разработчики кассы решили не связываться с Cookies для авторизации кассы и перенесли токен в LocalStorage (встроенное хранилище браузера на диске для настроек сайтов).

В файловой системе LocalStorage пишется в формате LevelDB (простая дисковая база ключ-значение от Google) по пути:
`%APPDATA%\moysklad-kassa\Local Storage\leveldb\`

В этих файлах сессионный токен кассы лежит в формате Plaintext (абсолютно открытый текст без какого-либо шифрования).

## В чем проблема

1. Токен не защищен DPAPI и не зашифрован.
2. Любой софт или скрипт, запущенный от имени текущего пользователя, может открыть этот файл в режиме чтения и скопировать `authToken`.
3. Для этого не нужны права админа, не выскакивает окно UAC (окно контроля учетных записей Windows с вопросом подтверждения) и не требуется ввод пароля.
