# Модуль 1. Реальный стек и рантайм клиента

Программа заявляется как облачная касса с поддержкой фискализации (печать чеков по 54-ФЗ) и маркировки (государственная система Честный Знак).

В реальности десктопный клиент не является нативным приложением (программой, скомпилированной прямо под машинный код процессора на C++ или C#). Это упакованный сайт в каркасе Electron (упаковщик, который берет движок браузера Google Chrome и заворачивает веб-страницу в один исполняемый exe-файл).

## Зависимости из официального дистрибутива (package.json)

При распаковке официального пакета `moysklad-kassa` версии 4.352.0 в папке `/resources/app/` находится стандартный манифест зависимостей:

```json
{
  "name": "moysklad-kassa",
  "version": "4.352.0",
  "main": "main.js",
  "dependencies": {
    "@electron/remote": "2.1.3",
    "better-sqlite3": "12.11.1",
    "effector": "22.1.2",
    "koffi": "2.15.2",
    "serialport": "13.0.0",
    "winax": "3.6.9"
  }
}
```

## Как работают компоненты

- `better-sqlite3` - библиотека для прямого чтения и записи локальной базы данных SQLite без использования сетевых сокетов.
- `koffi` и `winax` - инструменты FFI (Foreign Function Interface - механизм, позволяющий скриптам на JavaScript вызывать бинарные библиотеки Windows DLL). Используются для дергания старых драйверов фискальных регистраторов АТОЛ и Штрих-М через COM/ActiveX.
- `effector` и `react` - стандартные фронтенд-библиотеки для переключения экранов кассира, отрисовки каталога и кнопок.
- `Scala.js` - монорепа кассы написана на языке Scala и компилируется в один огромный JS-файл `web-retail-opt.js` (весит более 5 МБ).

## Итог по архитектуре

Приложение не использует механизмы защиты памяти Windows, не проверяет собственную целостность и ведет себя как обычный сайт, получивший доступ к файловой системе через Node.js.
