# Модуль 6. Поведение серверного аудита

В МоемСкладе есть журнал Audit Log (журнал аудита, куда записываются действия пользователей).

В ходе теста было проверено, какие действия кассы фиксируются в этом журнале:

## 1. Пассивное чтение (GET) и ошибки доступа (403)

- Одиночный GET-запрос настроек кассы (`/settings/retailstore`).
- Опрос остатков и чеков.
- Попытка запросить данные чужой точки продаж с получением ошибки `HTTP 403 Forbidden` (ошибка 12013).
- **Результат в журнале:** 0 записей. Чтение данных сервером в журнал аудита не вносится.

## 2. Запрос нового токена кассы (POST /admin/attach)

Когда касса привязывается к магазину через метод `POST /api/posap/1.0/admin/attach/{id}` с вводом логина и пароля, сервер генерирует новый ключ и фиксирует событие:

```json
{
  "source": "posapi",
  "eventType": "replacetoken",
  "entityType": "retailstore",
  "name": "Точка 1",
  "info": {
    "additionalInfo": "(IP-адрес, User-Agent)"
  }
}
```

## Итог по логированию

Серверный аудит фиксирует только мутации (изменения данных) и перевыпуск токенов (`replacetoken`).

Использование уже существующего токена кассы для чтения баланса денежного ящика и чеков для серверов МоегоСклада выглядит как обычный опрос связи работающей кассы и не оставляет следов в журнале безопасности.
