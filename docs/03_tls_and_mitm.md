# Модуль 3. Сетевой уровень и перехват трафика

В банковских терминалах и платежных шлюзах стандартом является Certificate Pinning (жесткое вшивание отпечатка открытого ключа сервера прямо в исполняемый код программы). Если кто-то пытается подменить сертификат или перехватить трафик, программа намертво разрывает соединение.

## Анализ кода main.js

В декомпилированном главном файле кассы `main.js` обработка сертификатов сведена к стандартной функции Electron:

```javascript
electron_1.app.on('certificate-error', (event, webContents, url, error, certificate, callback) => {
    const isIp = /^https:\/\/\d+\.\d+\.\d+\.\d+/.test(url);
    if (isIp) {
        event.preventDefault();
        callback(true); // Для локальных IP-адресов ошибки SSL глушатся в ноль
    } else {
        callback(false); // Для доменов проверка отдается стандартному хранилищу ОС
    }
});
```

## Что это означает на практике

1. Для локальных адресов касса полностью игнорирует ошибки сертификатов (сделано для сетевых банковских терминалов и фискальников с самоподписанными сертификатами).
2. Для домена `online.moysklad.ru` программа вызывает `callback(false)`. Это говорит движку браузера проверить сертификат через стандартное хранилище Windows (`certmgr.msc`).
3. В клиенте полностью отсутствует защита от MITM (Man-in-the-Middle - перехват данных посередине провода). Если в систему поставить локальный сертификат перехватчика (Burp, mitmproxy, Fiddler или корпоративный антивирусный шлюз), клиент слепо доверяет ему и отдает все чеки, суммы и справочники в открытом виде.
