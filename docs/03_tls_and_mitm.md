# Модуль 3. Сетевой уровень и перехват трафика

В надежных программах передачи финансовых данных обязательным стандартом является Certificate Pinning (жесткое вшивание отпечатка сертификата безопасности прямо в код программы). При наличии такой защиты программа намертво привязана к подлинному серверу и отказывается работать, если между ней и сервером кто-то пытается слушать трафик.

## Построчный разбор обработчика сертификатов в main.js

В декомпилированном главном файле кассы `main.js` находится функция перехвата ошибок защищенного соединения:

```javascript
// Перехватываем любое событие ошибки проверки безопасности соединения:
electron_1.app.on('certificate-error', (event, webContents, url, error, certificate, callback) => {
    // Проверяем: если запрос идет на прямой цифровой IP-адрес (например 192.168.1.50):
    const isIp = /^https:\/\/\d+\.\d+\.\d+\.\d+/.test(url);
    if (isIp) {
        // Отменяем стандартное решение браузера заблокировать опасное соединение:
        event.preventDefault();
        // Принудительно говорим браузеру: "Все безопасно, открывай соединение":
        callback(true);
    } else {
        // Для обычных доменов (online.moysklad.ru):
        // Отдаем проверку сертификата стандартному хранилищу Windows:
        callback(false);
    }
});
```

## Что это означает простыми словами

1. **Для прямых IP-адресов:** Касса вообще не проверяет подлинность сервера. Любой фальшивый или самоподписанный сертификат принимается без предупреждений.
2. **Для доменов МоегоСклада:** Программа вызывает `callback(false)`. Это команда движку Chromium проверить сертификат через стандартный список доверенных сертификатов Windows (`certmgr.msc`).
3. **Уязвимость к MITM-перехвату:** Если на компьютере установлен локальный корневой сертификат (например, программа перехвата трафика Fiddler, Charles, mitmproxy или корпоративный антивирусный фильтр), касса слепо доверяет ему. Весь зашифрованный трафик кассы расшифровывается на лету открытым текстом.
